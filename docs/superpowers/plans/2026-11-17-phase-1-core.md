> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>

>
> **Revision 3 (2026-11-17):** validated by implementing it in a scratch copy twice. Revision 1: 49 mutants, 20 survived, plus an adversarial review. Revision 2: 79 mutants, 11 survived. Revision 3 adds the 7 tests that kill those survivors (checked against them) and fixes the defects that run found. The one remaining survivor (empty `messages` accepted) is equivalent once the "at least one user message" validator exists, so the redundant `min_length` was dropped.

**Goal:** A tenant admin creates an API key, a developer calls `POST /v1/chat` with it, and the call is routed, answered by the fake provider, audited and billed, all in memory.

**Architecture:** FastAPI app built by `create_app()`, which wires an `AppState` (async repositories, providers, price table, clock) into `app.state`. Domain logic lives in small pure modules (`auth/keys.py`, `routing/rules.py`, `billing/pricing.py`); HTTP routes in `api/` only translate between HTTP and those modules. Repositories are `async` Protocols with in-memory implementations, so Postgres (next plan) replaces them without touching routes. All routes are `async def` (a sync route runs in a threadpool and would race on the in-memory dicts).

**Tech Stack:** Python 3.12, FastAPI, Pydantic v2, pydantic-settings, pytest (+ FastAPI `TestClient`), uv, ruff, mypy strict.

**Spec:** `docs/plan.md` (tasks 1.1-1.7 and 1.10) and the Features list in `README.md`. Out of scope, next plan: 1.8 PostgreSQL, 1.9 Anthropic provider.

## Global Constraints

- Python `>=3.12`; no new runtime dependencies beyond `pyproject.toml`, except declaring `anyio>=4` explicitly in Task 7 (already installed via FastAPI).
- `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy`, `uv run pytest` all pass after every task. Snippets below are not ruff-formatted: after pasting, run `uv run ruff format .` before the checks.
- Written from scratch: no code, names or structure copied from current or past employers. No LLM-as-a-judge.
- API keys: format `llmgw_<prefix>_<secret>`, `prefix` = 12 lowercase hex chars (`secrets.token_hex(6)`), `secret` = `secrets.token_urlsafe(32)`. Stored hash = `sha256(f"{prefix}:{secret}")` hex. The secret is never stored, logged or returned after creation.
- Roles: `admin`, `developer`, `viewer`. Only `developer` calls `/v1/chat`; `admin` manages keys and routing; `viewer` and `admin` read audit/usage.
- Money: `decimal.Decimal`, USD, prices per million tokens; every cost is quantized to `Decimal("0.000001")` with `ROUND_HALF_UP` and serialized as a string with 6 decimals (zero is `"0.000000"`).
- Only successful calls cost money; every `/v1/chat` request that passes authentication, role and body validation writes exactly one audit record (401/403/422 write none).
- Every timestamp comes from the injected clock (`AppState.clock`), never `datetime.now()`.
- Every error response is `{"error": {"code": str, "message": str}}`, including FastAPI validation (422), unknown routes and unhandled exceptions. Never echo request input or stack traces.

## Review Focus

1. Secrets contain `_` and `-`: a key must still parse (split on the first two `_` only). Task 3.
2. Whitespace-only content (`"   "`) must be rejected with 422 `invalid_request` through the API, not only at model level. Tasks 2 and 7.
3. Cross-tenant actions (revoke a key, read audit, routing rules) must never affect or reveal another tenant. Tasks 4, 5, 8.
4. A call dated before the model's first price must not reach the provider: 503 `pricing_unavailable`, audited as error with cost 0. Task 7.
5. Hostile headers and queries (no/empty/prefix/non-ASCII admin token, non-Bearer scheme, naive datetimes, `start >= end`) must produce 401/422, never 500. Tasks 4 and 8.

**Interfaces:**
- `api/errors.py`: `class ApiError(Exception)` (`status_code: int`, `code: str`, `message: str`) and `register_error_handlers(app: FastAPI) -> None`, registered with `@app.exception_handler(...)` for: `ApiError`; `RequestValidationError` → 422 `invalid_request` (message lists field paths only, never `input`); Starlette `HTTPException` → its status with `not_found` / `method_not_allowed` / `http_error`; `Exception` → 500 `internal_error`, generic message, logged server-side.
- `auth/deps.py`:
  - `@dataclass(frozen=True) class Principal`: `tenant_id`, `key_id`, `key_prefix`, `role: Role`.
  - `get_principal` dependency: `Authorization` must be `Bearer <key>` (scheme case-insensitive); anything else, unknown prefix, wrong secret or revoked → 401 `invalid_api_key`.
  - `require_role(*roles: Role) -> Callable[..., Awaitable[Principal]]` → 403 `forbidden` otherwise.
- Admin token: header declared `x_admin_token: Annotated[str | None, Header()] = None`; compared as bytes (`hmac.compare_digest(given.encode(), expected.encode())`); missing/empty/wrong → 401 `invalid_admin_token`.
- Endpoints (`api/admin.py`):
  - `POST /v1/admin/tenants` (admin token) body `{"name": str (1..100)}` → 201 `{"tenant_id", "admin_key"}`.
  - `POST /v1/admin/keys` (admin) body `{"role": Role}` → 201 `{"key_id", "prefix", "role", "key"}`; on `DuplicateKeyPrefixError` regenerate up to 3 times, then 500 `internal_error`.
  - `GET /v1/admin/keys` (admin) → 200 `[{"key_id", "prefix", "role", "created_at", "revoked_at"}]`.
  - `DELETE /v1/admin/keys/{key_id}` (admin) → 204 (also when already revoked: idempotent, original `revoked_at` kept); 404 `key_not_found` if not in caller's tenant; 409 `last_admin_key` only when the target is an *active* admin key and no *other active* admin key exists. The check uses `list_for_tenant` (no get-by-id). In memory it is race-free (no await yields between list, check and revoke). **Open for the Postgres plan:** the `KeyRepository` Protocol has no transaction hook, so two concurrent DELETEs of the last two admin keys could both succeed; add either an atomic `revoke(..., forbid_last_admin=True)` or a unit-of-work context before 1.8.
- Added after the Task 4 review:
  - **Body size limit:** FastAPI decodes the JSON body *before* auth dependencies run, so a malformed body gets 422 even without a key (documented, pinned by a test), and an anonymous caller could make the server buffer any size. `api/limits.py` adds a pure-ASGI `BodySizeLimit` (Settings `max_body_bytes`, default 1 MiB): a declared `Content-Length` over the limit gets 413 `payload_too_large` without reading the body; chunked bodies are counted as they stream. Verified against a real uvicorn server, not only TestClient.
  - 422 messages never echo client-invented keys: `extra_forbidden` errors are reported as `<parent> (unknown field)`.
  - Non-standard HTTP statuses keep the error shape (phrase lookup can't crash the handler).
  - `create_tenant` issues the admin key *before* storing the tenant, so a failed key issue leaves no orphan tenant.
  - 401 responses carry `WWW-Authenticate: Bearer`.
  - `/docs` and `/openapi.json` stay public for this phase (they list routes, nothing secret); hide them behind a setting before a real deployment.
- `tests/helpers.py`: `ADMIN_TOKEN = "test-admin-token"`; `bootstrap(client, name="acme") -> tuple[str, str]`; `create_key(client, admin_key, role) -> str`; `find_key_id(client, admin_key, key) -> str` (matches the key's prefix); `auth(key) -> dict[str, str]`. Tests import with `from tests.helpers import ...`.

  - **Audit write never masks the original error:** `_write_audit` catches and logs store failures (with a reconcile line: id, tenant, key prefix, model, status, tokens, cost; no prompt). If the row of an **answered** call can't be written, the request **fails closed** with 500 `audit_unavailable` and the answer is not handed out; on a request that already failed, the original error (including a cancellation) still propagates.

  - The provider response is re-validated (`ChatResponse.model_validate(raw.model_dump())`): negative tokens or junk from a buggy provider → 502, never billed.
  - Provider failures are logged (provider, model, exception **type** only: upstream messages may echo prompts).
  - The shield is now tested with a real cancellation (route called inside an anyio task group, hanging provider, an audit repo that really awaits), including that the cancellation is re-raised. So the "known gap" above is closed.
  - Remaining equivalent mutant: the `_Outcome.error_code` default is never observable (every exception sets a code, success clears it); kept as defence in depth.
